PART 1 — System Context and Personal Experience (15 Points)

1. System Description, Purpose, Architecture, and Intended Users

The digital system evaluated in this performance audit is FeliVet Insight (v1.0.0; running on Flutter 3.x and Dart SDK ≥ 3.11). FeliVet Insight is an edge-AI mobile clinical triage tool engineered to assist cat owners, animal rescue volunteers, foster caregivers, and veterinary clinic intake assistants in performing rapid, non-invasive, privacy-preserving screening of common feline dermatological conditions directly from a smartphone photo.

The system architecture integrates three core subsystems:

  • Species & Image Quality Gatekeeper (MobileNetV2): An on-device classifier (cat_gatekeeper.dart, mobilenet_gatekeeper.tflite, 3.8 MB) that intercepts uploaded photos to ensure a feline subject is present and adequately framed before triggering heavy disease detection.
  • Dermatological Vision Detector (YOLOv8): A lightweight convolutional neural network (flutter_vision, best.tflite, 10.6 MB) optimized for on-device inference using the TensorFlow Lite XNNPack CPU delegate, trained to detect Scabies (Notoedric/Sarcoptic mange), Ringworm (Dermatophytosis), and Flea Allergy Dermatitis.
  • Deterministic Expert Triage Engine: A rule-based medical decision system (triage_engine.dart) that decouples raw visual confidence scores from clinical risk. It synthesizes visual evidence scores, lesion bounding box counts, inherent disease hazards, and owner-reported systemic symptoms into a prioritized urgency rating (Stable, Moderate, or High) accompanied by natural-language clinical reasoning and actionable care advice.

3. Observations: Successes, Bottlenecks, and Operational Failures

  • What Worked Well (Zero-Latency Local Privacy): Complete on-device processing via TFLite ensures that no pet photos, owner identifiers, or health records are transmitted over the network, upholding total data privacy and offline operational readiness.
  • Intelligent Species Gatekeeping: When tested with non-cat images (human skin, blankets, furniture), the MobileNet gatekeeper cleanly blocked execution and displayed a user-friendly modal offering specific camera framing tips rather than generating hallucinated false-positive disease classifications.
  • Clinical Safety Rules: In tests with Scabies, even when visual evidence was moderate (61%), the deterministic engine correctly factored in the disease's high clinical risk and accompanying symptoms to escalate urgency to High, successfully avoiding dangerous medical under-triage.
  • Cold-Start UI Thread Freezing (Defect): On the physical Infinix X6881, synchronous YOLOv8 model loading blocked the main Dart UI thread for 3,592 ms (~3.6 seconds) at 0 FPS with no progressive loading indicator, causing user disorientation.
  • Test Suite Regression Failure (Defect): Running the project's automated test suite revealed that widget_test.dart failed due to an active, unmanaged periodic timer in FollowUpReminderPanel and SplashScreen that was not cancelled upon widget disposal (!timersPending assertion failure).

PART 3 — Defect, Risk, Audit, and Compliance Review (20 Points)

1. Documentation of Two Verified Defects / UX Weaknesses

Defect 1: Asynchronous Timer Lifecycle Leak in UI Widgets
Description: FollowUpReminderPanel (follow_up_reminder_panel.dart) and SplashScreen (splash_screen.dart) instantiate periodic timers and ticker controllers but omit calling .cancel() inside their respective State.dispose() methods.
Reproduction Steps:
  1. Execute flutter test test/widget_test.dart in terminal.
  2. Test harness boots FeliVetApp on SplashScreen and advances past 4 seconds.
  3. Widget tree unmounts; automated test binding verifies tear-down state.
  4. Flutter framework throws: Assertion failed: line 2543 pos 12: !timersPending.
Impact: Crashes automated CI/CD test suites and causes background battery drain on mobile devices.
Defect 2: Synchronous Main-Thread Model Allocation UI Freeze
Description: Model weights and delegate compilation (best.tflite, 10.6 MB) execute synchronously on the main Dart UI isolate upon navigating to TriageScreenState.initState().
Reproduction Steps:
  1. Launch FeliVet on a physical Android handset with USB debugging enabled.
  2. Watch the screen transition from splash screen to the main dashboard.
  3. UI frame rate drops to 0 FPS for ~3,592 ms; screen gestures are completely frozen.
Impact: High UX severity; violates Android 16 ms frame budget guidelines and risks triggering ANR popups.

2. Analysis of Two Practical System Risks (Clinical & Operational)

  • Risk 1 (Clinical / Diagnostic) — Look-Alike Disease Misclassification:
    Possible Cause: YOLOv8 model is trained exclusively on 3 diseases (Scabies, Ringworm, Flea Allergy). Feline dermatological conditions with overlapping visual presentations (e.g., Feline Eosinophilic Granuloma Complex, bacterial pyoderma, pemphigus foliaceus) may be misclassified or missed entirely.
    Likelihood: Medium | Impact: High
    Practical Mitigation: The deterministic expert system enforces multi-symptom intake to escalate urgency regardless of visual confidence; displays prominent non-diagnostic disclaimers; and routes ambiguous cases directly to veterinary consultation.
  • Risk 2 (Operational / Technical) — Unbounded Local Storage Bloat:
    Possible Cause: High-resolution camera photos captured via ImagePicker and uncompressed PDF reports generated by PdfReportService are written to application document storage (path_provider) with no automated eviction, expiration, or quota policy.
    Likelihood: High | Impact: Medium
    Practical Mitigation: Implement a rolling FIFO retention cap in HistoryStorage limiting saved records to 30 scans, and downsample imported camera images to 640×640 JPEG prior to storage.

3. Audit and Regulatory Compliance Question

Audit Question: "Does the on-device storage of unencrypted feline health logs, diagnostic timestamps, and pet photographs in the local application sandbox comply with statutory data privacy standards (such as data minimization and user right to erasure under RA 10173 / Philippine Data Privacy Act of 2012), and are the application's disclaimers legally sufficient under veterinary licensing regulations to prevent liability for unauthorized veterinary medical practice?"

Evidence-Aware Analysis: While veterinary patient data is not governed by human HIPAA regulations, domestic pet photographs taken inside a user's residence frequently capture incidental personal data (household members, interior personal property, and embedded EXIF geolocation coordinates). FeliVet currently stores raw photos in local sandbox storage without stripping EXIF metadata. Furthermore, under Republic Act No. 9268 (Philippine Veterinary Medicine Act), diagnosing animal ailments is strictly restricted to licensed veterinarians. FeliVet adheres to good practice by labeling results as a 'triage aid' rather than a 'definitive diagnosis', but the software must ensure that EXIF metadata is stripped upon ingestion, and the 'Clear All History' button executes permanent disk unlinking rather than mere UI clearing.

PART 4 — Improvement Proposal and Continuous Quality (25 Points)

1. Three Traceable Quality Recommendations

  • Recommendation 1 — Asynchronous Isolate Model Loading & Skeleton UI:
    (a) Proposed Change: Offload TFLite model allocation to a background Dart Isolate or compute worker thread, accompanied by an animated skeletal loader.
    (b) Who Benefits: Feline owners and mobile users, particularly those operating budget Android smartphones.
    (c) Expected Improvement: Eliminates the 3.6-second UI freeze, maintains steady 60 FPS transitions, and prevents ANR dialogs.
    (d) Measurement: Zero dropped frames during cold start in Flutter DevTools Performance overlay; time-to-interactive < 150 ms.
  • Recommendation 2 — Timer Lifecycle Governance & Automated CI/CD Pipeline:
    (a) Proposed Change: Refactor SplashScreen and FollowUpReminderPanel to store timers in nullable variables (Timer? _timer) and explicitly invoke _timer?.cancel() in dispose(). Configure GitHub Actions CI for automated regression checks.
    (b) Who Benefits: Development team, contributors, and end-users (preserves device battery life).
    (c) Expected Improvement: 100% automated test pass rate; zero background timer leaks.
    (d) Measurement: Automated regression pass rate in flutter test increases from 95% to 100% (20/20 tests passing).
  • Recommendation 3 — Automated FIFO Cache Eviction & Image Compression:
    (a) Proposed Change: Intercept camera images upon selection, strip EXIF metadata, compress to 640×640 JPEG, and enforce a 30-entry FIFO retention cap in HistoryStorage.
    (b) Who Benefits: Long-term users with constrained physical device storage.
    (c) Expected Improvement: Reduces on-device storage footprint per scan by ~85% (from ~2.5 MB raw photo to <350 KB).
    (d) Measurement: Storage directory size audited across 30 consecutive scans (target: total app data bounded ≤ 50 MB).

2. Plan–Do–Check–Act (PDCA) Improvement Cycle for Recommendation 2

• PLAN: Conduct a static code audit across all StatefulWidget classes in /lib/screens and /lib/widgets for uncollected Timer, AnimationController, and StreamSubscription instances. Define acceptance criteria: zero pending timers post-widget unmount and 100% automated pass rate in CI/CD without !timersPending assertion failures.
• DO: (1) In splash_screen.dart, assign the 3,800 ms timer to Timer? _splashTimer and invoke _splashTimer?.cancel() in dispose(). (2) In follow_up_reminder_panel.dart, verify that _timer?.cancel() executes cleanly in dispose(). (3) In test/widget_test.dart, update test harness to call await tester.pumpAndSettle(). • CHECK: Execute flutter test across all 9 test suites; verify 20/20 test cases pass with zero assertion errors. Audit Flutter DevTools Memory tab to verify unmounted screen instances are garbage-collected with zero retained heap.
• ACT: Standardize asynchronous resource disposal rules in CONTRIBUTING.md. Require passing automated CI checks before merging pull requests into the main release branch.
